## 1. 背景与问题

营销与品牌从业者需要快速理解「不同品牌会如何表达同一个产品」。直接问 LLM「X 品牌会怎么打广告」往往得到泛化答案，因为模型缺少该品牌的真实声音约束；而逐篇阅读品牌资料又低效。

**核心问题**：如何让 AI 稳定、可信地扮演不同品牌，并在一场讨论中呈现品牌间真实的表达差异？

**我们的答案**：用结构化「品牌声音卡」约束角色 + 多轮编排讨论（陈述 → 交锋 → 总结），把抽象的品牌风格变成可感知、可对比、可教学的内容。

## 2. 产品目标

1. **可用**：零部署、双击即用的单文件产品，任何访问者都能完整体验；
2. **可信**：角色扮演严格遵循真实声音数据，总结输出可解释的分歧与共识；
3. **可扩展**：用户能自定义品牌角色、自选品牌阵容，不依赖开发改代码；
4. **可控成本**：单场讨论提示词控制在 1KB 级声音卡 + 3 次调用，Key 自备。

## 3. 目标用户与场景

| 用户 | 场景 | 诉求 |
| --- | --- | --- |
| 品牌 / 营销从业者 | 想快速看 4-5 个品牌对同一产品会怎么打 | 直观对比品牌调性差异 |
| 产品经理 / 求职者 | 面试展示、案例复盘 | 低成本做一场「多品牌视角」的推演 |
| 学习型用户 | 理解品牌表达体系 | 讨论中的分歧点即教学点 |
| 普通体验者 | 无 Key、零成本体验 | 演示模式完整走通流程 |

## 4. 范围界定

**In（本期）**
- 自动圆桌、推荐圆桌、灵感卡
- 与品牌对话（搜索 / 筛选 / 收藏）
- 自定义角色（三字段）与自由选人圆桌
- 历史回看、资料附件、暗色模式、中英输出

**Out（本期不做）**
- 账号体系、云端保存与多人协作
- 品牌数据自动更新（当前由数据文件内嵌驱动）
- 讨论的实时流式输出、多模型并行对比
- 移动端适配（当前最小宽度 1024px）

## 5. 功能需求

### 5.1 信息架构

```
顶部栏 56px：Logo（品牌 Talk）｜ 输出语言｜暗色模式｜更多｜支持
├─ 左侧导航 240px：＋新对话 ｜ 对话搜索 ｜ 历史列表（emoji+标题+日期）｜ 设置
└─ 主内容（三区块）
   ├─ 自动圆桌：话题输入（placeholder：输入话题，AI 自动匹配嘉宾…）＋ 开始 →
   │            行业 / 市场 / 阵容预览 / 换一换 / 灵感卡 / 📎资料
   ├─ 推荐圆桌：6 个案例卡片（2 行 × 3 列）
   └─ 与品牌对话：搜索框（搜索或输入任意品牌…）＋ 创建角色
                  标签筛选（全部/消费品/SaaS/开发工具/金融科技/游戏/AI/B2B）
                  已选品牌条（清空 / 开始圆桌）
                  角色卡片网格（3 列：logo 占位 / 收藏星标 / ＋选人 / 名称 / 行业 / 开始对话）
```

### 5.2 功能清单

| 模块 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 自动圆桌 | 输入话题 → 按行业匹配 4 品牌 + 1 主持人，3 次 LLM 调用完成两轮讨论 + 总结 | P0 | 行业可选 6 类；阵容可「换一换」 |
| 推荐圆桌 | 6 个预置案例，点击直接开始（无 Key 走演示） | P0 | 便携榨汁杯 / 智能手环等 |
| 灵感卡 | 本场品牌各生成 headline + why | P1 | 复用本场声音卡 |
| 与品牌对话 | 84 品牌按行业展示；搜索框匹配品牌名 | P0 | 输入未知名字回车 → 弹创建表单 |
| 品牌收藏 | 星标收藏，收藏优先排序 | P1 | 存 localStorage |
| 自定义角色 | 表单：品牌名字（必填）/ 行业（下拉可选可输入）/ 系统提示词 | P0 | 可编辑、可删除；行业筛选生效 |
| 声音卡注入 | 自定义角色按「行业 + 系统提示词」生成声音卡进入讨论 | P0 | 与内置品牌同通道，零额外调用 |
| 自由选人 | 卡片「＋」多选（上限 4），选择条 chips 移除 / 清空 / 开始圆桌 | P1 | 先跳二级页面填话题再开始，按点击顺序组队，不足自动补齐 |
| 历史回看 | 每场讨论自动保存，左侧栏回看 / 清空（上限 10 条） | P0 | 保存两轮记录 + 总结 + 阵容 |
| 资料附件 | 插入文件参与讨论上下文 | P1 | ≤5 份 / ≤200KB / 每份 ≤6000 字 |
| 演示模式 | 未配置 Key 或强制演示时用预录数据 | P0 | 明示「演示模式」 |
| 设置 | API Base URL / Key / 模型名 / 强制演示 | P0 | Key 仅存本机 |

### 5.3 核心流程

**流程 A：自动圆桌**
```
输入话题 → 选行业/市场 → 点「开始 →」
  ├─ 有 Key：注入本场声音卡 → 第 1 轮陈述（5 角色 JSON）
  │           → 第 2 轮交锋（互相回应，agree/disagree/build-on）
  │           → 主持人总结（共识/分歧/建议）→ 存历史
  └─ 无 Key：演示数据全流程展示，并提示配置 Key
```

**流程 B：自定义角色**
```
点「＋ 创建角色」→ 填 品牌名字/行业/系统提示词 → 保存
  → 卡片出现在品牌网格（带行业标签）
  → 点「开始对话」加入阵容，或「＋」选入圆桌
  → 开桌后 voiceCardFor() 命中该角色，声音卡原文注入 system prompt
```

**流程 C：自由选人圆桌**
```
在品牌卡片点「＋」（上限 4 位）→ 选择条显示已选
  → 点「开始圆桌 →」→ 跳转二级页面确认阵容
  → 填写话题 / 选择市场 → 点「开始讨论 →」按点击顺序组队 4 位嘉宾
  → 主持人按行业默认 → 不足 4 位自动补齐 → 进入讨论
```

### 5.4 关键交互细节

- 卡片「＋」选中态：描边高亮 + 按钮变 ✓，点击可取消；
- 已选 chips：点击即移除，避免误触有「清空」兜底；
- 创建角色：行业留空 = 自定义；行业输入任意文本均合法；
- 搜索框回车：已知品牌 → 直接加入阵容；未知品牌 → 弹出预填名字的表单；
- 全部交互即时反馈（toast），无 Key 提示常驻于输入区下方。

## 6. 数据说明

**数据来源**：HuggingFace `manifesta/brandvoice-marketing-briefs`（CC0），共 84 个品牌。

**数据模型**：`{ brand, category, voice:{tone, personality[], voice_summary}, examples[], channels[], total_samples }`

**行业分布**：AI 11 / Consumer 13 / SaaS 14 / B2B 8 / Fintech 12 / Dev Tools 17 / Gaming 8 / General 1。

**内嵌策略**：全量内嵌于 `BRAND_VOICES`（单文件零请求）；讨论时只注入本场 4 品牌 + 主持人共 5 张声音卡，控制 token。

**本地存储**：API Key / 设置 / 历史（10 条）/ 收藏 / 自定义角色均存于 localStorage，无任何数据上传。

## 7. 非功能需求

| 项 | 要求 |
| --- | --- |
| 部署 | 单文件 HTML，双击可用，可静态托管（GitHub Pages / Vercel / OSS） |
| 性能 | 首页无网络请求即渲染；单场讨论 3 次 LLM 调用 |
| 隐私 | API Key 仅存本机；除用户主动发起外无任何外部请求 |
| 兼容 | 现代浏览器；最小宽度 1024px |
| 健壮 | 模型返回 JSON 解析失败时给出可读错误；可随时停止 / 点击跳过动画 |
| 成本 | 声音卡按场抽取，单场提示词 ~1KB 级；附件有上限与截断 |

## 8. 验收标准（抽样）

- [x] 未配置 Key 时，推荐圆桌/自动圆桌可用演示数据完整走通并写入历史
- [x] 配置 Key 后，3 次调用按序完成，总结包含 consensus / divergences / actions
- [x] 84 个品牌卡片全部渲染，8 个行业标签可筛选，收藏可持久化
- [x] 创建含行业与提示词的角色后，开桌声音卡包含用户原文指令
- [x] 「＋」最多选 4 位，选择条可移除/清空，开桌阵容 = 用户点击顺序 + 自动补齐
- [x] 附件超限/超长时给出提示并安全截断，不破坏讨论

## 10. 衡量指标（建议）

- **体验**：无 Key 用户完成整场演示的转化率（≥ 60%）
- **质量**：总结 JSON 可解析率（≥ 95%）；角色不漂移人工抽检（无 A 品牌说 B 风格文案）
- **扩展**：自定义角色创建数 / 选人圆桌使用占比（体现可控编排价值）
- **成本**：单场调用平均 token 与耗时（声音卡抽取后的优化效果）
