# 品牌 Talk · 产品设计文档

> 基于当前最新版（v2.3：含选人二级页面、历史 ⋯ 菜单 / 置顶 / 文件夹等）整理。页面为单文件 HTML，零后端、零依赖，双击即用。

| 项 | 内容 |
| --- | --- |
| 产品名称 | 品牌 Talk（品牌声音圆桌） |
| 产品形态 | 单文件 Web 应用（桌面优先，最小宽度 1024px） |
| 核心价值 | 让用户输入一个话题，看 4 个品牌 + 1 位主持人按各自真实声音「吵一架」，产出可对比、可执行的营销思路 |
| 数据规模 | 内置 84 个品牌声音卡，8 大行业 |
| 运行模式 | 配置 API Key 走真实模型；未配置自动进入演示模式 |

---

## 1. 产品定位与价值主张

**一句话**：一个「品牌人格模拟器」——把抽象的品牌调性变成一场可以观看、可以对比、可以教学的多角色圆桌讨论。

**为什么有存在价值**
- 直接问 LLM「X 品牌会怎么打」只能得到泛化答案；本项目用结构化声音卡约束角色，产出「一听就是该品牌」的表达；
- 讨论中强制交锋（agree / disagree / build-on），把品牌差异显性化，比单条文案更有教学价值；
- 单文件交付，零部署，3 分钟就能给别人演示，适合作为作品集与面试案例。

## 4. 核心功能设计

### 4.1 自动圆桌（主路径）
- 输入话题（placeholder「输入话题，AI 自动匹配嘉宾…」），选择行业（6 类）、市场（全球/中国/欧美/日韩）、输出语言（中文/English/双语）；
- 系统按行业给出阵容（4 品牌 + 1 主持人），支持「🔄 换一换」随机替换；
- 点「开始 →」后执行三轮编排：开场陈述 → 交锋 → 主持人总结，全程打字机动画，可「停止」或点击舞台跳过；
- 总结固定输出：核心观点表 / 共识 / 分歧点（含教学含义）/ 3 条可执行建议。

### 4.2 推荐圆桌（快速体验）
- 6 个预置案例（榨汁杯 / 智能手环 / 团队协作工具 / 开发者测试平台 / 数字钱包 / AI 写作助手）；
- 点击卡片自动填充产品描述与对应行业并开始讨论，无 Key 时走演示。

### 4.3 与品牌对话（品牌库）
- 84 个品牌按 8 大行业标签筛选，搜索框支持模糊匹配；
- 星标收藏（收藏优先排序，持久化）；
- 卡片结构：品牌首字色块 Logo + 收藏星标 + 「＋」选人 + 品牌名 + 行业胶囊 + 开始对话；
- 搜索框输入未知名字回车 → 弹出创建表单（预填名字）。

### 4.4 自定义角色（数据扩展）
- 「＋ 创建角色」弹出三字段表单：品牌名字（必填）/ 行业（下拉可选 + 自由输入，留空为自定义）/ 系统提示词（描述说话风格、立场、口头禅）；
- 角色卡片带行业标签与「✏️ 编辑」「🗑 删除」；
- 运行时优先读取自定义角色，把「行业 + 系统提示词」原样注入声音卡，与内置品牌同通道扮演。

### 4.5 自由选人圆桌（编排可控）
- 品牌卡片「＋」多选（上限 4 位）：选中卡片描红边 + 按钮变 ✓，可再次点击取消；
- 已选品牌条：chips 可点击移除、一键清空、「开始圆桌 →」；
- 点「开始圆桌 →」跳转**二级页面**：确认阵容（嘉宾 + 主持人 chips）、填写话题（必填）、选择市场，再点「开始讨论 →」进入圆桌；
- 组队规则：按用户点击顺序排列 4 位嘉宾，主持人按行业默认分配，不足 4 位自动从当前阵容补齐；已选话题/市场自动同步回自动圆桌。

### 4.6 对话历史管理（左侧栏）
- 每场讨论自动保存（上限 10 条），按「今天 / 昨天 / 月-日」标注；
- 支持搜索对话、点击回看（瞬时渲染，不播动画）、高亮当前条目；
- 每条历史右侧「⋯」菜单：
  - 📁 创建文件夹：弹窗输入名称，对话移入文件夹（已在文件夹内则显示「移出文件夹」）；
  - 📌 置顶：置顶到列表顶部并显示 📌 标记（可取消）；
  - 🗑 删除：删除对话并同步清理置顶/文件夹引用；
- 顶部「更多 ▾ → 清空历史」一键清空历史、置顶与文件夹。

### 4.7 品牌资料附件
- 插入 .txt/.md/.csv/.json 等文件参与讨论上下文：最多 5 份、单份 ≤200KB、每份最多注入 6000 字（超长截断并标注）；
- 附件块展示文件名/大小/字数，可单独删除；讨论记录会保存附件清单。

### 4.8 设置与演示模式
- 设置弹窗：API Base URL / API Key / 模型名 / 「始终使用演示模式」；
- Key 仅存本机 localStorage，页面直连 API，无任何中间服务器；
- 未配置 Key 或强制演示时，使用内置演示数据（便携榨汁杯案例）完整走通全流程，并常驻提示「未检测到 API Key」。

### 4.9 视觉与主题
- 浅色背景 #fafafa + 卡片白底，朱红主色 #e5484d；
- 系统无衬线字体，标题 14-16px / 正文 13px，卡片圆角 8px / 按钮 6px，阴影仅 hover 出现；
- Emoji 作为视觉装饰（规避品牌真实商标）；支持暗色模式（持久化）。

## 5. 关键用户路径

```
路径 A：快速体验
  首页 → 推荐圆桌卡片 →（无 Key）演示讨论 → 查看总结 → 侧栏回看

路径 B：自定义品牌讨论
  与品牌对话 → ＋ 创建角色（名字/行业/提示词）→ 保存
  → 卡片「开始对话」加入阵容 或 「＋」选入 → 二级页面填话题 → 开始讨论

路径 C：自选阵容推演
  品牌卡片「＋」选 4 位 → 已选条「开始圆桌 →」→ 二级页确认阵容 + 填话题
  →「开始讨论 →」→ 两轮讨论 + 总结 → 自动存入历史

路径 D：历史管理
  侧栏搜索 → 打开「⋯」→ 置顶 / 移入文件夹 / 删除 → 点击回看
```

## 6. 数据设计

### 6.1 品牌声音卡（内嵌 BRAND_VOICES，84 条）
```jsonc
{
  "brand": "Stripe",
  "category": "Fintech",                 // AI/Consumer/SaaS/B2B/Fintech/Dev Tools/Gaming/General
  "voice": {
    "tone": "confident and supportive",
    "personality": ["innovative", "reliable"],
    "voice_summary": "Stripe empowers businesses of all sizes..."
  },
  "examples": ["Build your business on financial infrastructure..."],
  "channels": ["ad", "onboarding step"],
  "total_samples": 50
}
```

### 6.2 本地存储（localStorage）
| Key | 内容 |
| --- | --- |
| brandRoundtableSettings | Base URL / Key / 模型 / 强制演示 |
| brandRoundtableHistory | 讨论记录（上限 10 条，含 id / ts / 两轮记录 / 总结 / 阵容 / 附件清单） |
| brandRoundtableCustoms | 自定义角色 `{name, industry, systemPrompt}` |
| brandRoundtableFavs | 收藏品牌 |
| brandRoundtablePinned | 置顶对话 id |
| brandRoundtableFolders | 文件夹 `{name, items:[对话 id]}` |
| brandRoundtableTheme | 明暗主题 |

### 6.3 LLM 编排协议
- 每次调用：`{model, temperature, messages:[system, user], max_tokens:3000}`，要求严格 JSON 输出，兼容 markdown 代码块包裹并容错解析；
- 只注入本场 5 张声音卡（4 品牌 + 主持人），约 1KB 级，控制 token 与角色串味风险；
- 三轮分工：陈述（展示差异）→ 交锋（强制互评，制造差异）→ 总结（收敛为共识/分歧/建议）。

## 7. 状态与反馈设计

| 状态 | 呈现 |
| --- | --- |
| 加载中 | 状态栏 spinner + 文案（「演示模式：主持人开场…」等分阶段文案） |
| 成功 | toast「讨论完成，已保存到历史」 |
| 失败 | 状态栏红色错误 + toast，给出可读原因 |
| 停止 | 「已停止」提示，动画立即结束 |
| 空状态 | 无历史 / 无匹配对话 / 无匹配品牌，均有引导文案 |
| 边界 | 选人超过 4 位、附件超限、创建重名角色、未填话题等均有 toast 拦截并说明 |

## 8. 非功能设计

- **性能**：首页零网络请求即可渲染；讨论仅 3 次 LLM 调用；
- **隐私安全**：Key 只存本机；纯静态文件，不包含任何密钥，部署不泄露；
- **健壮性**：模型 JSON 解析失败给出可读错误；可随时停止 / 跳过动画；
- **兼容**：现代浏览器；桌面优先（≥1024px）；离线可演示；
- **可维护**：单文件内按「数据层 / 常量 / 渲染 / 编排 / 初始化」分区；179 项 DOM 冒烟测试守护。
