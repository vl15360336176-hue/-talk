# 品牌 Talk · 项目文档

> 一个单文件、零依赖的「品牌声音圆桌」网页应用：把 84 个品牌的真实声音卡数据内嵌在 HTML 中，让用户输入一个产品话题，AI 就扮演 4 个品牌 + 1 位主持人，围绕该话题展开两轮圆桌讨论并输出结构化总结。

- **形态**：单文件 HTML（约 160KB），双击即用，无构建、无后端、无第三方依赖
- **数据**：内嵌 84 个品牌声音卡（HuggingFace manifesta/brandvoice-marketing-briefs，CC0）
- **能力**：自动圆桌 / 灵感卡 / 推荐圆桌 / 与品牌对话 / 自定义角色 / 自由选人 / 历史回看 / 附件注入 / 暗色模式 / 中英输出
- **版本**：v2.2（见「版本演进」）

---

## 1. 项目背景与目标

品牌营销文案往往「一听就是某个品牌的风格」。本项目想验证一个问题：

> 能否让 LLM 基于真实的品牌声音数据（tone / personality / 代表文案），稳定地「扮演」不同品牌，并在同一场讨论里展现出彼此的性格差异？

传统做法是把品牌资料整段塞进提示词，token 消耗大、角色容易互相串味。本项目的解法是：

1. 为每个品牌建立结构化「声音卡」，只注入**本场 4 品牌 + 主持人**的声音卡（约 1KB 级），省 token；
2. 用 3 次编排调用（第一轮陈述 → 第二轮交锋 → 主持人总结）把「角色扮演」和「讨论推进」分开，保证角色不漂移、总结有结构；
3. 以单文件形式交付，零部署成本，任何人都能双击打开体验。

---

## 2. 核心能力

| 模块 | 说明 |
| --- | --- |
| 自动圆桌 | 输入产品话题，按行业自动匹配 4 品牌 + 1 主持人，AI 完成两轮讨论 + 结构化总结 |
| 灵感卡 | 让本场品牌针对产品各自生成营销灵感卡（headline + 为什么这么打） |
| 推荐圆桌 | 6 个预置案例卡片，一键进入演示讨论 |
| 与品牌对话 | 84 个品牌按行业分类展示，支持搜索、收藏、筛选 |
| 自定义角色 | 用户创建「品牌名字 + 行业 + 系统提示词」的自定义角色，可编辑、可删除，并作为声音卡注入讨论 |
| 自由选人 | 品牌卡片「＋」选人（最多 4 位），按用户选择组建阵容再开圆桌 |
| 品牌资料附件 | 插入 .txt/.md/.csv/.json 等文件（最多 5 份、单份 ≤200KB、每份最多注入 6000 字） |
| 历史回看 | 对话历史存 localStorage（最多 10 条），左侧边栏随时回看 |
| 演示模式 | 未配置 API Key 时自动使用内置演示数据（便携榨汁杯案例），完整功能可离线体验 |

## 3. 产品架构

### 3.1 总体架构

```
┌──────────────────────────────────────────────┐
│  index.html（单文件）                          │
│  ├── 视图层：顶部栏 / 左侧历史导航 / 三区块首页   │
│  ├── 数据层：BRAND_VOICES（84 卡）内嵌在 script │
│  ├── 状态层：localStorage（Key/历史/角色/收藏） │
│  └── 编排层：3 次 LLM 调用（JSON 严格输出）      │
└──────────────────┬───────────────────────────┘
                   │ fetch /chat/completions
                   ▼
          用户自配的 LLM API（Key 仅存本机）
```

设计要点：

- **数据即代码**：品牌数据序列化后直接内嵌为 `BRAND_VOICES` 常量，页面零请求即可完整渲染；
- **Key 不出本机**：API Key 仅存 localStorage，请求由浏览器直发，无中间服务器；
- **演示兜底**：`forceDemo` 或未配置 Key 时走预录数据，保证任何访问者都能体验全流程。

### 3.2 数据模型

```jsonc
{
  "brand": "Stripe",
  "category": "Fintech",            // 行业：AI / Consumer / SaaS / B2B / Fintech / Dev Tools / Gaming / General
  "voice": {
    "tone": "confident and supportive",
    "personality": ["innovative", "reliable", "adaptable"],
    "voice_summary": "Stripe empowers businesses of all sizes..."
  },
  "examples": ["Build your business on financial infrastructure..."],
  "channels": ["ad", "onboarding step"],   // 保留字段
  "total_samples": 50                       // 保留字段
}
```

辅助结构：

- `INDUSTRY_LINEUP`：6 个行业阵容，每组 4 品牌 + 1 主持人（按声音差异最大化原则挑选）；
- `HOST_DESC`：6 位主持人的性格补充，注入 system prompt 保证主持人不偏不倚；
- `BRAND_COLORS` + `brandColor(name)`：固定配色优先，新品牌按名称哈希自动生成稳定色。

### 3.3 LLM 编排流程（3 次调用）

1. **第一轮·开场陈述**：注入「产品 case + 市场 + 输出语言 + 本场声音卡（5 张）+ 附件」，要求 5 个角色按各自声音开场，严格输出 JSON；
2. **第二轮·交锋**：把第一轮记录回灌，要求每个品牌回应至少一个其他品牌（agree / disagree / build-on），强制产生性格差异；
3. **主持人总结**：以主持人身份输出 `intro / table / consensus / divergences / actions` 结构化总结。

每次调用 `max_tokens=3000`、`temperature` 分阶段控制（陈述/交锋/总结各取 0.7/0.7/0.3 级别），并兼容模型返回的 markdown 代码块包裹。

## 4. 版本演进（体现产品进化）

### v1.0 · 初始原型（从 0 到 1）

**变更**：单文件 HTML 原型，12 个品牌的声音卡，核心是「自动圆桌」：输入话题 → 匹配行业阵容 → 三轮 LLM 调用完成讨论；附 6 个推荐圆桌案例、品牌列表、「如果只能抄一个」式总结。

**关键决策**：先验证「声音卡 + 多角色编排」能否让 LLM 稳定扮演不同品牌，因此刻意不做 UI 打磨，聚焦核心链路。

**收获**：验证了 3 次编排的结构有效；发现「角色扮演」依赖声音卡质量，且总结中的“只能抄一个”式输出与圆桌教学定位不符，为 v1.1 提供方向。

### v1.1 · 产品化改造（从「脚本页」到「产品」）

**变更**：
- 对话历史移入左侧边栏（新对话 / 搜索 / 回看 / 清空），补上「今天 / 昨天」式时间标签；
- 移除「如果只能抄一个」，总结改为「共识 + 分歧 + 可执行建议」，强调教学价值；
- 新增品牌资料附件（文件注入讨论上下文）、暗色模式、输出语言选择；
- 品牌列表按行业分组，顶部加「与品牌对话」搜索框（搜索或输入任意名字），并参考主流产品完成新版面：240px 左侧导航 + 顶部栏 + 三区块首页，朱红主色。

**关键决策**：从「演示工具」转向「可回看、可配置、可扩展的对话产品」，把用户高频诉求（历史、资料、语言）前置。

**收获**：页面从「能跑」变成「能展示」；附件功能带出「上下文注入」这一 LLM 应用核心议题。

### v2.0 · 数据层升级（12 → 84 个品牌）

**变更**：将 84 个品牌声音卡（brand_voices_full.json）整体内嵌为 `BRAND_VOICES`，页面布局与逻辑不动，只改数据层：
- 新增 `brandColor(name)` 兜底：原 12 品牌保留固定配色，新品牌按名称哈希生成稳定色；
- 类目标签补 `General → 通用`，保证 8 个行业全部可正确显示与筛选。

**关键决策**：数据内嵌而非请求加载——保持单文件、双击即用、离线可体验；同时用「只注入本场声音卡」控制 token 成本（当时讨论过 RAG，结论是 84 条 × 几百字的数据量不需要，全量内嵌 + 按场次抽取更简单可靠）。

**收获**：产品从「演示样例」升级为「覆盖 8 大行业、84 个品牌的通用工具」。

### v2.1 · 用户可扩展（自定义角色）

**变更**：
- 「创建角色」从单一名字输入升级为**三字段表单**：品牌名字 / 行业（可下拉可选、可自由输入）/ 系统提示词；
- 自定义角色进入声音卡注入链路：`voiceCardFor(name)` 优先读取用户角色，把「行业 + 系统提示词」原样注入 system prompt，让 LLM 严格按用户定义扮演；
- 角色卡片支持行业标签、编辑（回填）、删除；搜索框输入不存在的品牌名回车，自动弹出预填表单。

**关键决策**：让用户能扩展品牌库而不改代码——自定义角色与内置品牌走同一条声音卡通道，零额外接口调用，只增加一段提示词文本。

**收获**：产品从「只读数据」变成「可创作」，用户可以用自己的品牌（如蜜雪冰城）参与圆桌。

### v2.2 · 编排可控（自由选人圆桌）

**变更**：
- 每张品牌卡片新增「＋」选择按钮（选中描边 + 对勾），可多选最多 4 位品牌；
- 新增「已选品牌」选择条：chips 可点选移除、一键清空、一键「开始圆桌」；
- 点「开始圆桌」先进入二级页面：确认阵容 + 填写话题 + 选择市场，再点「开始讨论 →」进入圆桌；
- 开桌时按用户点击顺序组建 4 位嘉宾阵容，主持人按行业默认分配，不足 4 位自动从当前阵容补齐。

**关键决策**：把「系统自动匹配」升级为「用户可控编排」——自动圆桌保留给快速体验，选人圆桌满足「我就想听这几个品牌吵一架」的明确诉求。

**收获**：产品的使用路径从「看演示」延伸为「自定义 + 自选 + 讨论」，闭环完整。

## 5. 关键技术决策与取舍

| 决策 | 取舍 |
| --- | --- |
| 单文件零依赖 | 部署成本为零、双击即用，代价是数据与逻辑耦合，后续大改需整体维护 |
| 数据内嵌 vs RAG | 数据量（84 卡）远小于 token 预算，全量内嵌 + 按场次抽取优于引入检索链路 |
| 只注入本场声音卡 | 5 张卡 × 约 200 字 ≈ 1KB 级提示词，显著低于全量注入，避免角色串味 |
| 3 次调用编排 | 比单次调用更稳（角色不漂移、总结有结构），代价是 3 倍延迟与成本 |
| 演示模式兜底 | 无 Key 也能完整体验，但预录数据无法响应用户输入，需明示 |
| Key 存本机 | 无服务器、隐私好，但受浏览器 CORS 与本地环境限制 |
| 附件截断（5 份 / 200KB / 6000 字） | 控制提示词体量与调用成本，牺牲长文档的完整性 |

---

## 6. 已知限制

- 演示模式为预录数据，无法响应用户自定义输入（需配置 API Key）；
- 依赖浏览器直连 LLM API，部分代理/网关存在 CORS 限制时需自配中转地址；
- 数据为英文原声卡，中文场景依赖模型翻译演绎；
- 单文件体积随数据增长（当前约 160KB），极端扩展需考虑拆分。

- **v2.3**：自定义角色支持删除确认与批量管理；选人阵容持久化到 localStorage；
